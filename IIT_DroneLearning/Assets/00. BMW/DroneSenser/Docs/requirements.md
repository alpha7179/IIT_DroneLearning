# 요구사항 문서

## 소개

본 문서는 Unity ML-Agents 기반 드론 시뮬레이션을 위한 26방향 레이캐스트 센서 시스템의 요구사항을 명세합니다. 센서 시스템은 드론 중심에서 여러 방향으로 레이를 발사하여 공간 인식을 제공하며, 장애물 감지 및 환경 인식을 통해 자율 내비게이션과 충돌 회피를 가능하게 합니다.

## 용어집

- **드론_센서_시스템**: 드론에 공간 인식을 제공하는 레이캐스트 기반 센서 구현체
- **레이_센서_API**: 센서 데이터 접근 및 설정을 위한 공개 인터페이스
- **레이캐스트**: 레이 방향을 따라 충돌을 감지하는 Unity 물리 연산
- **센서_레이어**: 센서의 수직 그룹 (Top, Top-Middle, Middle, Middle-Bottom, Bottom)
- **센서_방향**: 레이어 내 센서의 수평 방위 (8개 주방위/부방위)
- **충돌_거리**: 드론 중심에서 레이를 따라 감지된 장애물까지의 측정 거리
- **최대_감지_범위**: 레이가 장애물을 감지할 수 있는 최대 거리
- **DroneAgent**: 드론 행동을 제어하는 기존 ML-Agents Agent 클래스
- **DronePhysics**: 드론 이동 및 회전을 위한 기존 6-DOF 물리 컴포넌트
- **센서_데이터**: 26개 레이의 거리 측정값 집합

## 요구사항

### 요구사항 1: 26방향 센서 구성

**사용자 스토리:** 드론 개발자로서, 드론이 주변 모든 공간 방향의 장애물을 감지할 수 있도록 26방향 레이캐스트 센서 시스템을 원합니다.

#### 수락 기준

1. 드론_센서_시스템은 드론 중심 위치에서 정확히 26개의 레이를 발사해야 합니다
2. 드론_센서_시스템은 레이를 5개의 센서_레이어로 구성해야 합니다: Top 레이 1개, Top-Middle 레이 8개, Middle 레이 8개, Middle-Bottom 레이 8개, Bottom 레이 1개
3. 각 8개 레이 센서_레이어에 대해, 드론_센서_시스템은 수평면 주위로 45도 간격으로 레이를 균등하게 분배해야 합니다 (N, NE, E, SE, S, SW, W, NW)
4. Top 레이는 구면 좌표계에서 수직 위쪽(0°, 90°, 0°)을 가리켜야 합니다
5. Bottom 레이는 구면 좌표계에서 수직 아래쪽(0°, -90°, 0°)을 가리켜야 합니다
6. Top-Middle 레이는 수평면 위 30도에서 60도 사이의 고도각을 가리켜야 합니다
7. Middle 레이는 0도 고도에서 수평으로 가리켜야 합니다
8. Middle-Bottom 레이는 수평면 아래 30도에서 60도 사이의 고도각을 가리켜야 합니다

### 요구사항 2: 레이 센서 API 인터페이스

**사용자 스토리:** 드론 개발자로서, ML-Agents 및 다른 컴포넌트와 센서 시스템을 통합할 수 있도록 깔끔한 API를 통해 센서 데이터에 접근하기를 원합니다.

#### 수락 기준

1. 레이_센서_API는 26개의 충돌_거리 값을 배열로 반환하는 메서드를 제공해야 합니다
2. 레이_센서_API는 특정 센서_레이어와 센서_방향에 대한 충돌_거리를 반환하는 메서드를 제공해야 합니다
3. 레이_센서_API는 최대_감지_범위를 설정하는 메서드를 제공해야 합니다
4. 레이_센서_API는 개별 레이를 활성화 또는 비활성화하는 메서드를 제공해야 합니다
5. 레이_센서_API는 디버깅을 위해 Unity 에디터에서 레이 방향을 시각화하는 메서드를 제공해야 합니다
6. 레이_센서_API는 정규화된 거리 값(0.0~1.0)을 반환해야 하며, 0.0은 충돌 없음을, 1.0은 최대 범위 충돌을 나타냅니다

### 요구사항 3: 레이캐스트 실행 및 충돌 감지

**사용자 스토리:** 드론 개발자로서, 드론이 환경을 정확하게 인식할 수 있도록 정확한 장애물 감지를 원합니다.

#### 수락 기준

1. 레이가 장애물과 교차할 때, 드론_센서_시스템은 드론 중심에서 충돌 지점까지의 충돌_거리를 기록해야 합니다
2. 레이가 최대_감지_범위 내에서 어떤 장애물과도 교차하지 않을 때, 드론_센서_시스템은 충돌_거리를 0.0(정규화)으로 기록해야 합니다
3. 드론_센서_시스템은 드론의 현재 위치와 회전을 기준으로 월드 공간 좌표에서 레이캐스트를 수행해야 합니다
4. 드론_센서_시스템은 물리 업데이트와 동기화하기 위해 매 FixedUpdate 주기마다 모든 센서 판독값을 업데이트해야 합니다
5. 드론_센서_시스템은 드론 자체의 콜라이더와의 충돌을 무시해야 합니다
6. 레이 경로를 따라 여러 장애물이 존재할 때, 드론_센서_시스템은 가장 가까운 충돌_거리만 기록해야 합니다

### 요구사항 4: DroneAgent와의 통합

**사용자 스토리:** 드론 개발자로서, ML-Agents가 학습에 센서 데이터를 사용할 수 있도록 센서 시스템이 기존 DroneAgent와 원활하게 통합되기를 원합니다.

#### 수락 기준

1. 드론_센서_시스템은 드론 GameObject에 부착 가능한 Unity MonoBehaviour 컴포넌트로 구현되어야 합니다
2. 드론_센서_시스템은 Unity ML-Agents VectorSensor 관찰 수집과 호환되는 센서 데이터를 제공해야 합니다
3. DroneAgent는 강한 결합 없이 레이_센서_API를 통해 센서_데이터에 접근할 수 있어야 합니다
4. 드론_센서_시스템은 DronePhysics 기능을 수정하거나 의존하지 않아야 합니다
5. 드론_센서_시스템은 첫 번째 FixedUpdate 호출 전에 초기화되어야 합니다

### 요구사항 5: 설정 가능한 센서 매개변수

**사용자 스토리:** 드론 개발자로서, 다양한 환경과 사용 사례에 맞게 센서 시스템을 조정할 수 있도록 Unity Inspector에서 센서 매개변수를 설정하기를 원합니다.

#### 수락 기준

1. 드론_센서_시스템은 최대_감지_범위를 기본값 50미터로 설정 가능한 매개변수로 노출해야 합니다
2. 드론_센서_시스템은 Top-Middle 및 Middle-Bottom 레이어의 고도각을 설정 가능한 매개변수로 노출해야 합니다
3. 드론_센서_시스템은 감지 가능한 Unity 레이어를 필터링하기 위한 레이어 마스크 설정을 노출해야 합니다
4. 드론_센서_시스템은 Scene 뷰에서 레이를 표시하기 위한 디버그 시각화 토글을 노출해야 합니다
5. 디버그 시각화가 활성화된 경우, 드론_센서_시스템은 색상 코딩으로 레이를 그려야 합니다: 충돌 없음은 녹색, 충돌 감지는 빨간색

### 요구사항 6: 성능 최적화

**사용자 스토리:** 드론 개발자로서, 시뮬레이션이 성능 저하 없이 여러 드론을 동시에 실행할 수 있도록 효율적인 센서 성능을 원합니다.

#### 수락 기준

1. 드론_센서_시스템은 단일 FixedUpdate 주기 내에 26개의 레이캐스트를 모두 완료해야 합니다
2. 드론_센서_시스템은 가비지 컬렉션을 최소화하기 위해 센서 데이터용 할당된 배열을 재사용해야 합니다
3. 드론_센서_시스템은 매 프레임마다 재계산하는 대신 레이 방향 벡터를 캐시해야 합니다
4. 디버그 시각화가 비활성화된 경우, 드론_센서_시스템은 어떤 디버그 그리기 작업도 수행하지 않아야 합니다
5. 드론_센서_시스템은 RaycastHit 배열을 할당하지 않고 Unity의 Physics.Raycast 메서드를 사용해야 합니다

### 요구사항 7: 향후 카메라 통합을 위한 확장성

**사용자 스토리:** 드론 개발자로서, 나중에 대규모 리팩토링 없이 정면 카메라 기능을 추가할 수 있도록 센서 시스템이 확장 가능하기를 원합니다.

#### 수락 기준

1. 드론_센서_시스템은 레이캐스트 로직과 데이터 접근을 분리하는 모듈식 아키텍처를 사용해야 합니다
2. 레이_센서_API는 카메라 정렬을 위한 전방 레이 방향을 조회하는 메서드를 제공해야 합니다
3. 드론_센서_시스템은 동일한 GameObject에 추가 센서 컴포넌트 부착을 방해하지 않아야 합니다
4. 드론_센서_시스템은 향후 카메라 통합을 위한 좌표계 및 변환 계층 구조 가정을 문서화해야 합니다
